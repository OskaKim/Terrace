# 0009 4 つのプロジェクトと文書を 1 つのリポジトリにまとめる

- 日付: 2026-09-30

## 背景

最初は MasterData・Map・Server・Client を別々のリポジトリとして作り([prompts/](../prompts/README.md))、文書だけをルートのリポジトリで管理していた([ADR 0007](0007-docs-in-root-repository.md))。GitHub にも 5 つのリポジトリとして上げた。

その後、複数の AI セッションに並列で実装させ、人間は PR をマージするだけ、という進め方を目指すことにした。5 つに分かれたままだと次の不都合があった。

- 通信の定義やマップの形を変えると、1 つのタスクが Server・Client・文書の複数の PR に割れ、マージの順番まで気を配る必要がある
- Server は兄弟のフォルダを相対パスで参照するので、並列の作業場は 5 つをひと揃い並べて作らなければならない
- 「この時点の 5 つの組み合わせ」を記録する仕組みが無い

## 決定

- `Terrace` リポジトリに 4 つのプロジェクトをフォルダとしてまとめる。フォルダの名前と並びは変えない
- 履歴は保つ。各リポジトリの履歴を「ファイルがそのフォルダの下にある形」に書き換えてから、マージコミットで取り込んだ
- 無視と改行の設定は、プロジェクトごとの `.gitignore` / `.gitattributes` をそのまま使う
- submodule にはしない

## 理由

- 1 タスク = 1 ブランチ = 1 PR にできる。共有コードの変更・Client への複製・文書の直しを同じ変更に入れられる
- 作業場は `git worktree` を 1 つ切るだけで揃う
- ビルドの相対参照([ADR 0004](0004-share-code-by-copy-csharp9.md))はフォルダの並びに頼っているだけなので、何も変えずに動く
- 履歴が浅いうちにまとめる方が安い

## 引き換えにしたもの

- プロジェクトを単独で取ってくることはできない。Unity のクライアントだけが欲しくても全体を取る
- 取り込む前のコミットは、取り込み前のリポジトリとはハッシュが変わっている(作者・日付・内容は同じ)
- Windows ではパスが長くなる。置き場所によっては `core.longpaths` が要る([guides/setup.md](../guides/setup.md))
- ADR 0004 と 0006 の本文にある「独立したリポジトリ」「兄弟リポジトリ」は、当時の言い方として残している。決定の中身(Client へは複製、Server へはプロジェクト参照、マップの正は Terrace.Map/maps)は変わらない
